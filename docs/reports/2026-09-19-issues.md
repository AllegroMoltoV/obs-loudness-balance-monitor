# issue #1・#2 の技術調査

調査日: 2026-09-19

## 対象

利用者は [#1: macOS Tahoe でのビルド失敗](https://github.com/AllegroMoltoV/obs-loudness-balance-monitor/issues/1) と [#2: ポータブル版 OBS の導入先と OBS 32.1 以降の互換性](https://github.com/AllegroMoltoV/obs-loudness-balance-monitor/issues/2) の両方を指定しました。

## #1: macOS Tahoe

- issue の報告は macOS 26.2、OBS 32.0.4 での `framework 'AGL' not found` です。詳細なリンクコマンドとビルドログは提示されていません。
- このリポジトリには `AGL` の直接参照がありません。`buildspec.json` は OBS 31.1.1 のソースと 2025-07-11 の OBS/Qt 依存パッケージを指定します。Qt は [AGL へのリンクを削除した変更](https://github.com/qt/qtbase/commit/cdb33c3d562) で、macOS 26 では AGL が使用できないと説明しています。今回のエラーがその Qt 依存から来た可能性がありますが、リンクコマンドでの確認はまだできていません。
- `v0.1.1` の [実行記録](https://github.com/AllegroMoltoV/obs-loudness-balance-monitor/actions/runs/20718761377)では、`macos-15` と Xcode 16.1 のジョブが成功しました。`macos-26` と Xcode 26.2 に変更した[検証実行](2026-09-19-tahoe-ci.md)は、リンク前に AutoMoc の配置ターゲット競合で失敗しました。
- GitHub の[ホストランナー一覧](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)に `macos-26` があります。その[イメージ一覧](https://github.com/actions/runner-images/blob/main/images/macos/macos-26-Readme.md)には Xcode 26.2 と macOS 26.2 SDK が記載されています。現在の Xcode 16.1 固定行をそのまま使うと、このランナーでは Xcode の切替先が見つからない見込みです。
- macOS 実機が手元にないため、GitHub Actions でコンパイルとリンクを検証します。今回の検証ではリンクまで到達していません。OBS の画面表示と音声解析の実動作は、Actions の成功だけでは確認できません。

## #2: Windows の配置と互換性

- OBS 公式の[プラグインガイド](https://obsproject.com/kb/plugins-guide)は、通常インストールで `C:\ProgramData\obs-studio\plugins` を推奨し、ポータブル版では OBS 展開先の `data/plugins` を指定します。必要な構造はプラグイン名のフォルダー内の `bin/64bit/<同名>.dll` と `data/locale/*.ini` です。`cmake/windows/helpers.cmake` のインストール規則と、この PC に配置済みの `v0.1.1` の構造は一致します。`README.md` と OBS Forum の掲載文にはポータブル版の配置先がありません。
- OBS 公式の[ポータブルモード手順](https://obsproject.com/kb/portable-mode)は、ZIP 版の展開と `portable_mode` ファイルまたは `--portable` 引数を示しています。[OBS 32.1 のリリースノート](https://obsproject.com/blog/obs-studio-32-1-release-notes)は音声ミキサーの変更を記載しています。
- この PC の OBS 実行ファイルは 32.2.2 です。2026-09-18 のローカル OBS ログでは、プラグイン `0.1.1` の読み込みとドック登録を確認しました。音声解析が正しいことまでは示しません。
- 同じログは終了時の `settings.json.tmp` 書き込み失敗を記録しています。`src/loudness-dock.cpp` は `obs_module_config_path("settings.json")` で得たパスへ保存しますが、設定ディレクトリを作っていません。この PC では該当ディレクトリが存在しませんでした。[OBS のモジュール API](https://docs.obsproject.com/reference-modules)は、この関数が存在しないファイルのパスも返すと説明しています。設定保持の失敗原因である可能性が高く、隔離した OBS 環境で再現が必要です。
- [OBS 32.1.2 の公式 release](https://github.com/obsproject/obs-studio/releases/tag/32.1.2)には Windows x64 ZIP があり、GitHub の asset digest は `sha256:8d97e4563bd8d22d03e63042aa7dccede1d555c9bd35ce8a9e5019b0d0201bf6` です。ポータブル版での実行検証に利用できます。

## 検証の境界

macOS 26 の AutoMoc の配置ターゲット競合を調べ、ビルドをリンクまで進めます。Windows ポータブル版の起動・設定保持は独立して確認できます。結果によって変更対象が変わるため、コード修正と公開手順はその後に決めます。利用者による OBS 実機の動作確認は、release 前に別途必要です。

# 録音・試聴の製品統合検証

## 対象

OBS 33.0.1の最終ミックスをメモリへ録音し、明示操作後に指定デバイスへ試聴出力する機能を検証した。製品コードの対象はコミット1d66222までとする。その後の変更は検証モジュールのみである。

## 成功した検証

- Windowsの隔離OBSで44.1 kHzと48 kHzの録音・試聴を実行した。3秒準備、手動終了、自然終了、再試聴の途中停止、標準モニター復元、オプトアウト、再録音準備の取消を確認した。
- 48 kHzで30秒上限による自動確定と全区間の試聴終了を確認した。
- 実際のOBS録画開始で試聴を中断し、標準モニターを復元した。録画中のボタン無効化と録画終了後の再準備を確認した。OBSは終了コード0で終了した。
- 存在しないデバイスへの出力でGetDevice HRESULT=0x80070490を表示し、標準モニターを復元した。同じ録音をADAT5/6へ再試聴できた。
- GitHub Actions 42169534410はWindows、macOS、Ubuntuの全ジョブで成功した。対象SHAは1d6622209368edf4d7aca03bfc99861bfa9a91cd。共通録音処理のテスト、通常配布物の導入・ロード、既存設定の再起動復元を含む。音声出力の実機検証とは区別する。

## 試験側の不備と修正

録画先のWindowsパスをINIへ直接書き込み、末尾のバックスラッシュとrが制御文字として解釈された。試験用パスをスラッシュ区切りへ修正した。通常OBSの設定は変更していない。

録画開始直後に100ミリ秒周期のボタン更新を判定して失敗した。失敗処理がOBSのイベント通知中にウィンドウを閉じ、OBSStudioAPI::on_eventでアクセス違反が発生した。終了処理を通知の外へ移し、録画停止後に閉じる形へ修正した。モニター復元の即時判定と表示更新後のボタン判定を分離した。修正後の中断試験が成功し、クラッシュは再発しなかった。この結果をもって今回のクラッシュ調査を終了する。

macOSでは製品ターゲットだけをビルドしていたため、追加した共通テストの実行ファイルが未生成だった。診断用ターゲットのビルドにlbm-preview-coreを追加し、CIの成功を確認した。

## 証拠と限界

機械可読の結果をdocs/logs/2026-11-06-preview-*.jsonに保存した。詳細ログは基準確認用ワークツリーの.logs/2026110629〜39に保存している。

Windowsの音声出力先はADAT5/6。入力は検証モジュールが生成する声・BGM相当の信号であり、利用者の声とBGMによる使い心地の確認を代行しない。今回の成功はOS出力処理の終了と操作状態の確認であり、物理出力波形の再測定ではない。

公開v0.1.3を隔離OBS33.0.1へ導入して保存した設定を、CI候補版への上書き後に復元できた。声・BGM、VAD、バランス目標、プリセット、ドック表示と非表示、メーター応答の3起動すべてが成功した。候補版の通常ProgramData導入はCIで確認し、ローカル更新試験は隔離配置による補助検証とする。

ローカルOBS終了ログにNumber of memory leaks: 1が残る。旧公開v0.1.3の対照試験でも同じ記録があり、今回の製品変更で増えた証拠はない。macOSとLinuxの実音声出力、利用者試用、最終配布物の検証・公開は未完了である。現在の進捗と次の作業はBeadsの親課題およびudy.5を正本とする。

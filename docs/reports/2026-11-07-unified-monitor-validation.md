# リアルタイムモニタと録音モニタの表示統合

## 目的と対象

依頼者AllegroMoltoVが承認した表示構成と計測定義を実装した。リアルタイムモニタ、録音の瞬時値、録音全体へ同じ順序で3評価と声・BGM・ミックスの数値を配置する。既存のLUFS、ピークdB、音量差LUを維持する。

録音のミックス解析には、選択した声とBGMの時刻をそろえたステレオPCMを使う。試聴音声にはOBSの最終ミックスを使う。両者の対象範囲をヘルプで説明する。既存のリアルタイム解析処理と出力バックエンドを変更していない。

## 計測と検証

瞬時値のLUFSは400ms窓を100ms間隔で計測する。平均には従来の3秒窓と音声検出条件を維持した。声とBGMの共通有効点から、有限のミックス値を持つ点でミックス平均を計算する。ミックスの逆相相殺で声とBGMの平均を失わせない。

ピークは100ms区間と録音全体で集計する。録音全体の集計には発声していない区間と100ms未満の末尾を含める。短い録音で平均LUFSが未確定でも、最大ピークとクリップ評価を表示する。

| 検証 | 結果 |
|---|---|
| 解析の境界試験 | 両レートの既存窓・分割入力・リセットに加え、短いピーク、末尾、−1/0dBFS、逆相相殺を確認 |
| Windows 48kHzの独立数値照合 | 瞬時120点、平均55点。LUFSとピークの最大差は0。評価も一致 |
| Windows 48kHzの試聴音声 | 録音PCMとの照合に成功 |
| Windows 44.1kHzの再試聴 | ソース選択とミックス基準を変えても、確定した録音解析値を維持 |
| Windows 44.1kHzの再録音 | 2秒の新しい録音で旧最大値を除去。平均不足と最大ピークを独立表示 |
| Windows 44.1kHzの試聴音声 | 初回、再試聴、再録音後の音声照合に成功 |

数値照合側ではOBSのカテゴリーPCMから別に加算・集計した。製品の解析関数を参照側から呼んでいない。音声照合には承認済みの先頭10msの振幅立上り差を適用し、取得開始の300ms先行を維持した。

## 表示と文案

共通ウィジェットで評価、メーター、数値の構成を統一した。日英文案のキーとプレースホルダーに差分はない。yomiyasuの指摘を承認文案と照合し、承認済み表現を維持した。

狭い英語表示で折り返し高さの不足を検出したため、QLabelの高さ計算を有効にした。文言と計測処理は変更していない。最終候補のドック幅232pxで、英語の3評価、全数値、録音全体の列見出しを確認した。6か所のヘルプでSpaceによる表示、Tabによる閉じるボタンへの移動、Spaceによる終了が成功した。日本語の録音結果も実機画面で確認した。

## 証拠と残作業

基準worktreeの`.logs/2026110733`〜`2026110748`と`.deps/preview-unified-*`にビルド、解析、実音声と画面の証拠を保存した。最終候補の表示とヘルプの証拠は`.deps/preview-layout-final-*`に保存した。最終候補でも独立数値照合と音声照合が成功した。

3OS CI、通常環境への退避付き導入、依頼者の再試用を残している。OS既定出力、停止時復元、保存設定の検証には、処理を変更していない既存の成功証拠を再利用する。ユーザーテストが完了するまで公開しない。

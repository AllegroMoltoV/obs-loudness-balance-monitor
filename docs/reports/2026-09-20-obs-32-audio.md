# OBS 32.1.2 ポータブル版の音声動作とソース解放

検証日: 2026-09-20

## 結果

隔離した Windows ポータブル版 OBS 32.1.2 で、プラグインが 2 件のメディアソースから音声を受け取り、声・BGM・ミックスの LUFS とピーク、および声と BGM の差を表示した。利用者が OBS の画面でメーターの動作と表示を確認し、問題は見当たらないと報告した。

最初のビルドでは、正常終了時に選択した 2 件のソースが解放されていないというエラーがログに残った。ソース参照をシーンコレクションの解放時に外す修正後、同じ隔離版で音声表示、空のシーンコレクションとの往復、正常終了を確認した。整理後の最終ビルドでも同じ検証が成功し、残存ソースのエラーは記録されなかった。これは Windows の隔離版 OBS 32.1.2 における結果であり、macOS 実機での動作や他の OBS 版を示すものではない。

## 検証条件

- リポジトリ: `D:\work\obs-loudness-balance-monitor`、ブランチ: `issue/1-2-validation`。プラグイン DLL は修正コミット `06f0959ad137cbbcc179cdf9f3904c118107d02f` の [GitHub Actions #35445133669](https://github.com/AllegroMoltoV/obs-loudness-balance-monitor/actions/runs/35445133669)から取得した Windows 生成物。SHA-256 は `dc72c96e33a0800436b64d91d6589ecb2927dc8b7ca4de3ee7bacaa1657f2cd9`。
- OBS は `.tmp/issue-2-portable/obs-32.1.2` に展開した隔離版。PID 12084 の実行ファイルはその `bin/64bit/obs64.exe`、ロード済みプラグイン DLL は `obs-plugins/64bit/loudness-balance-monitor.dll` と照合した。インストール済み OBS は操作していない。
- 入力は `.tmp/issue-2-audio/voice.wav` と `bgm.wav`。いずれも 48 kHz、16 bit、モノラル、10 秒のループ。前者は 440 Hz・RMS -18.93 dBFS、後者は 660 Hz・RMS -26.11 dBFS。`inspect_fixtures.py` で WAV を再読取りし、形式、長さ、SHA-256 を確認した。
- Computer Use の Windows 接続が `native pipe is unavailable` で失敗し、復旧手順後も変わらなかった。このため、利用者が隔離版 OBS の画面でメディアソースとプラグインを設定した。

## 音声表示と保存状態

利用者は OBS の音声ミキサーで `LBM検証・音声` と `LBM検証・BGM` のメーターが共に動くことを確認した。プラグインの画面表示として、次の値を報告した。

| 項目 | LUFS | ピーク |
| --- | ---: | ---: |
| 声 | -19.6 | -15.9 dB |
| BGM | -26.6 | -23.1 dB |
| ミックス | -18.8 | -13.1 dB |

「声 - BGM」は +7.0 LU と表示された。2 件のピーク値と声・BGM 間の約 7 LU の差は、生成した WAV の振幅と整合する。これらの画面値は利用者の報告であり、OBS のログや設定ファイルに実測値は保存されない。この観察だけで測定値の絶対精度、長時間安定性、録画・配信中の動作は証明しない。

OBS の「ファイル」→「終了」後、PID 12084 の消滅を確認した。隔離版のシーン JSON には、両メディアソースの WAV パス、`looping=true`、`volume=1`、`muted=false` が保存されている。プラグインの `settings.json` には `voice_source=LBM検証・音声`、`bgm_sources=[LBM検証・BGM]`、`balance_target=8.0` が保存された。OBS ログにはメディアソースの入力パスとループ設定、プラグインのロードとドック登録が記録された。メディアの読込み失敗やプラグインの設定保存失敗は検索して見つからなかった。ログのコピーは `.logs/issue-2-audio-2026-09-20.log` にある。

## ソース解放エラー

同じログの終了時には `Not all sources were cleared when clearing scene data` として、選択した `LBM検証・音声` と `LBM検証・BGM` の両方が記録された。ソースを選択していなかった 3 回の設定保存検証ログには、同じエラーがない。

[OBS 32.1.2 の `ClearSceneData()`](https://github.com/obsproject/obs-studio/blob/32.1.2/frontend/widgets/OBSBasic_SceneCollections.cpp#L1401-L1501)は、残存ソースを検出するとエラーを記録して `clearingFailed` を立てる。次のシーン集を読み込む際は、[エラー画面を表示して OBS を閉じる処理](https://github.com/obsproject/obs-studio/blob/32.1.2/frontend/widgets/OBSBasic_SceneCollections.cpp#L1079-L1089)がある。最初のビルドではシーンコレクション切替への影響を検証していなかった。

修正前のプラグインの `src/audio-capture.cpp` は `obs_get_source_by_name()` で選択したソースの強参照を取得し、`AudioCaptureManager` の破棄時に解放していた。`src/loudness-dock.cpp` はドックの破棄時に管理クラスを破棄する。[OBS 32.1.2 の終了順序](https://github.com/obsproject/obs-studio/blob/32.1.2/frontend/widgets/OBSBasic.cpp#L1807-L1829)では、シーンデータの解放が終了イベントより先である。プラグインが参照を保持したまま OBS のシーン解放に入ったことが、今回のエラーと整合する。参照の保持元を実行時に直接測定してはいないが、次節の修正前後の対照検証でこの説明を裏付けた。

## 修正と対照検証

修正前ログを `.tmp/issue-2-cleanup/check_cleanup.py` で検査すると終了コード 1 となり、`Not all sources were cleared when clearing scene data` を検出した。`AudioCaptureManager` が `OBS_FRONTEND_EVENT_SCENE_COLLECTION_CLEANUP` でソース参照を解放し、`OBS_FRONTEND_EVENT_SCENE_COLLECTION_CHANGED` で保存した選択名から再接続する修正を加えた。修正コミットは `94b13efac1df9927184b46a91de0ac63e7d57eda`。その後、参照の取得・解放と画面上の選択復元の重複を除去した最終コミットは `a1e35ad0f12ccddfbc74a6caac49fc5c095c2c4a`。

[最初の修正ビルド](https://github.com/AllegroMoltoV/obs-loudness-balance-monitor/actions/runs/35477720363)と[整理後の最終ビルド](https://github.com/AllegroMoltoV/obs-loudness-balance-monitor/actions/runs/35478512222)は、いずれも macOS、Windows、Ubuntu の全ジョブに成功した。最終 Windows DLL の SHA-256 は `7DC0095DC6A3F842ADAA7EAE009A6755426441EC955E427A9736F62943149BEF`。最終 DLL を隔離版 OBS の `obs-plugins/64bit` に置き、ロードされた実行ファイルと DLL のパスを照合した。

利用者は最終 DLL で、OBS ミキサーの 2 ソースとプラグインの声・BGM・ミックスの数値が動くこと、空のシーンコレクションに切り替えるとソース一覧から検証用ソースが消えること、元のコレクションへ戻すと選択と数値が復元すること、正常終了できることを報告した。OBS ログのコピーは `.logs/issue-2-cleanup-refactor-obs-2026-09-20.log`、SHA-256 は `8011DB1C985DC9F62332D7ED3E3ED30D13230B77BF7FDB6359C5DE99D831D8DB`。ログではシーンコレクション切替と終了後に `All scene data cleared` を確認し、残存ソースエラー、設定保存エラー、メモリリークの記録はなかった。修正前に失敗した検査は、このログでは終了コード 0 になった。`settings.json` は声・BGM の選択と目標 8.0 LU を保持し、元のシーン JSON は 2 件の WAV ソースを保持した。

同一コレクション内の空のシーンに切り替えた際、プラグインの数値が切替時点で止まったまま残るという別の観察があった。これは音声フレームが来ないと解析結果を更新しない現在の処理と整合する。音声測定の絶対精度と録画・配信中の動作は検証していない。
